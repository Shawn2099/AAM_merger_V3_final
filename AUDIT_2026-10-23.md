## 2. P0 — release blockers

### P0-1. The Unclassified “Save & Route” form is inert (critical)

**Evidence:** `templates/unclassified.html:47` places `<form>` directly inside `<tr>`, with the `<td>` elements and the submit button as **siblings** of the form. `dashboard.py:815` is the only reclassify endpoint.

HTML5 parsing inserts the form into the row and immediately pops it (“in row” insertion mode). The inputs and the `type="submit"` button have no form owner. The `hx-post` is on the empty form, so no submit event ever fires.

**Impact:** The only UI path to place a document that carries no content anchor — and the documented recovery path for permanently failed documents — does nothing. Clicking **Save & Route** or pressing Enter produces no request and no error. The 441-test suite never notices because every test POSTs `/unclassified/{id}/reclassify` directly.

**Fix:** put `hx-post="/unclassified/{{ doc.id }}/reclassify" hx-include="closest tr"` on the button, or move the form outside the table and reference it with `form="…"`. Add a browser/HTML-structure test that asserts the button has a form owner.

### P0-2. The Prefect midnight deployment is never registered when `schedule_timezone` is set (critical)

**Evidence:** `scripts/deploy_prefect.py:21-42`. `_schedule()` returns a `CronSchedule` object, then:

```python
sync_flow.to_deployment(name="aam-midnight-sync", cron=schedule, ...)
```

Prefect's `cron=` parameter is a **string**. Verified directly against the installed Prefect:

```
cron=obj  -> pydantic ValidationError: cron: Input should be a valid string
schedule=obj -> OK, CronSchedule(cron='0 0 * * *', timezone='Asia/Kolkata')
cron="0 0 * * *" -> OK (timezone=None, i.e. UTC)
```

`scripts/setup_test_rig.ps1:268-272` runs the deploy script and only prints a **warning** if it exits non-zero, then continues. The host looks healthy, `/sync` works manually, but the nightly job does not exist.

`tests/test_prefect_schedule.py:40-47` only checks that `_schedule()` returns the right object; it never calls `to_deployment()`.

**Impact:** On the documented install (`schedule_timezone: Asia/Kolkata` in `config.example.yaml`), the entire nightly automation is absent. If the timezone is omitted, a deployment is registered but runs at 00:00 **UTC** (05:30 IST).

**Fix:** `sync_flow.to_deployment(..., schedule=_schedule(cfg), ...)` and drop `cron=` (or pass `cron=CRON` plus `schedule=`). Add a test that calls `to_deployment()` (no `.apply()`) and asserts `deployment.schedules[0].schedule.timezone`.

### P0-3. A sterile split-parent can be attached from Unclassified and duplicates pages in the delivered packet (high)

**Evidence:** `extraction.py:343-352` creates the parent with `doc_type=COMBINED`, `is_split_parent=True`, `po_set_id=None`, no line items, but keeps the full combined `stored_path`.
`dashboard.py:57-73` (`_holding_area_query`) includes every `po_set_id IS NULL` row with **no `is_split_parent` exclusion**.
`dashboard.py:815-899` (reclassify) has **no `is_split_parent` guard** and accepts `SI`/`PO`/`DN` from the dropdown.

**Scenario (verified end to end):** PO+DN+SI set plus a 3-page combined PDF. Reclassify the parent as `SI` with the same PO number → it attaches; reconciliation passes on the child lines; merge includes the parent’s full combined PDF **in addition** to the three child pages → **6-page packet**. The wrong/duplicated document is what the CA receives.

`po_sets.py:305` and `dashboard.py:565` already refuse split parents on other paths; this one was missed.

**Fix:** add `Document.is_split_parent.is_(False)` to `_holding_area_query` (and to `unplaced_count`), and return 409 in `reclassify_document` when `doc.is_split_parent`.

### P0-4. An ambiguous DN/SI is attached anyway by `group_document` (high)

**Evidence:** `grouping.py:132-133`:

```python
if doc.po_reference_ambiguous and dtype in ANCHOR_TYPES:   # ANCHOR_TYPES == ("PO",)
```

The two sweep paths (`grouping.py:203`, `grouping.py:319`) refuse **all** ambiguous documents. The primary post-extraction path does not: an `SI`/`DN` with two printed PO numbers is attached to the first PO the VLM reported.

**Scenario:** an SI covering PO-A and PO-B, `po_reference_ambiguous=True`, `po_no_normalized="A"`. `group_document` attaches it to A. PO-B is left waiting for an invoice that already arrived. Where line numbers happen to collide, A can reconcile and merge with content that partly belongs to B; otherwise A quarantines as `unmatched_vendor_line`.

**Fix:** drop the `dtype in ANCHOR_TYPES` qualifier for the ambiguity check; keep set **minting** restricted to PO. Return `ambiguous_po_number` and leave the document in the holding area. Add a test for an ambiguous DN/SI through `group_document`.

### P0-5. Merge is not atomic, and unreadable source PDFs never quarantine (high)

**5a. Direct write to the final name.** `merge.py:148-172` writes `PdfWriter` directly to `out`; `merge_po_set` commits the DB **after** the file write (`merge.py:249-257`). A crash, power loss or disk-full between the two leaves a truncated `output/INV-123.pdf` with `merged_output_path=NULL`. The next attempt hits `_resolve_output_path` (`merge.py:140-144`) → `MergeNamingError` → `quarantined` as `packet_naming_failed`, with the misleading message “belongs to another PO Set”. The corrupt file remains in the output folder.

`append_customs_to_merged_packet` already does temp + `replace` (`merge.py:415-421`); the primary merge paths do not.

**5b. Unreadable source aborts reconciliation.** `merge.py:163` calls `PdfReader`; `merge_po_set` catches only `FileNotFoundError` (`merge.py:250-252`); `reconcile_po_set` catches only `MergeNamingError` (`reconciliation.py:506-507`).

Verified with a probe: one corrupt DN member → `PdfStreamError: Stream has ended unexpectedly` escapes `reconcile_po_set`. The set stays `pending`, `reconcile_reason=None`, no output; the nightly sweep logs the failure and retries forever (`flows/sync.py:410-418`). Encrypted PDFs behave the same (`FileNotDecryptedError`).

**5c. Missing file / zero lines are silent.** When a stored PDF is missing, `merge_po_set` returns `None`; when all documents have zero line items, the W-22 guard returns `None` (`merge.py:224-230`). In both cases `reconciliation.py:527-532` restores the prior status, writes no reason, and the set sits on `pending` with “Awaiting further processing” — the exact “quarantine shown as a wait” failure PRODUCT §3 forbids.

Probe (all three sides with zero line items): result `{'status': 'pending', 'merged_output_path': None, 'flags': []}` — not merged, but no reason and no operator guidance.

**Fix:**
- Write to a unique temp file in the output folder, `os.replace` it, then commit; clean up the temp on failure (and treat a same-set stale file as own, not “another set”).
- Catch pypdf `PdfReadError`/`PdfStreamError`/`FileNotDecryptedError` and missing files at the reconcile level; map to a new reason `packet_source_unreadable` (or quarantine with the offending filename).
- Quarantine/reason for `not po_lines` unconditionally, and for a merge refusal with zero evidence.

### P0-6. Stored XSS / broken Preview via `original_filename` in an Alpine expression (high)

**Evidence:** `templates/po_set_detail.html:314` and `templates/unclassified.html:109`:

```html
@click="$store.pdfDrawer.open('/documents/{{ d.id }}/preview', '{{ d.original_filename }}')"
```

Jinja escapes `'` to `&#39;`, but the browser decodes character references in attribute values; Alpine then compiles the decoded string with `new Function`.

- An everyday vendor file `Bob's invoice.pdf` becomes `open('…', 'Bob's invoice.pdf')` → `SyntaxError`; Preview silently does nothing.
- A crafted filename (`x');fetch('/po_sets/1/force_merge',{method:'POST'});//.pdf`) executes in the app origin when an operator clicks Preview. Filenames come from the input folder (`ingestion.py:75`).

**Fix:** put the URL and filename in `data-*` attributes and read them via `$el.dataset`, or emit them with `|tojson`; never interpolate into a JS literal.

## 5. Design decisions (not bugs — decide explicitly)

1. **Customs ON overwrites a quarantine/mismatch with `blocked_customs`** (`customs.py:73-82`, pinned by `test_customs.py:143-164`). A verified quantity failure disappears from the status while the customs gate is open; the reason string remains. PRODUCT §3 says a quarantine leaves only by a human. Either preserve the prior status alongside the customs gate or document the override.
2. **Re-uploading the same customs pair rebuilds and appends a second `customs_append` audit row.** Content is idempotent; the audit records each press. Intentional.
3. **`customs_doc_count` counts distinct types, not documents.** Correct for the two-type gate; a second CUSTOMS doc does not raise it.
4. **Force Merge bypasses every gate and justification is optional.** Intended; ensure the operator understands the packet may be commercially wrong.
5. **No authentication.** Accepted; CSRF/Host hardening is not documented.
6. **One PO document per set.** Configurable (`single_po_document: true`); turning it off sums baselines.
